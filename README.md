# UEMP — سامانه مدیریت رخداد شهری

نسخه MVP موبایل‌محور سامانه مدیریت، تحلیل و پیگیری رخدادهای شهری. پروژه با Next.js App Router، Prisma و SQLite ساخته شده و به‌صورت PWA قابل نصب است. پس از قرار گرفتن روی دامنه HTTPS می‌توان از همین پروژه APK مبتنی بر Trusted Web Activity ساخت.

## امکانات اصلی

- ثبت‌نام و ورود آزمایشی با OTP
- ثبت رخداد با تصویر، GPS/نقشه و توضیحات
- بهینه‌سازی تصویر روی موبایل پیش از آپلود
- تحلیل هوش مصنوعی و تحلیل کلمه‌کلیدی جایگزین
- داشبورد شهروند، مدیر و اپراتور سازمان
- PWA کامل با آیکن‌های استاندارد، نصب روی گوشی و صفحه آفلاین
- Prisma + SQLite مناسب اجرای MVP روی یک VPS تک‌نمونه‌ای
- کنترل دسترسی API بر اساس نقش و مالکیت رخداد
- endpoint سلامت در `/api/health`

## اجرای محلی

پیش‌نیاز: Node.js 20 و npm.

```bash
npm ci
cp .env.example .env
npx prisma migrate deploy
npm run dev
```

سپس `http://localhost:3000` را باز کنید. سرویس‌ورکر فقط در build تولیدی فعال می‌شود.

## تنظیم متغیرهای محیطی

فایل `.env.example` را به `.env` کپی و مقادیر زیر را تنظیم کنید:

- `DATABASE_URL`: برای ساختار فعلی مقدار `file:./dev.db` را نگه دارید.
- `JWT_SECRET`: یک رشته تصادفی حداقل ۳۲ کاراکتری؛ در سرور الزامی است.
- `OTP_MODE=demo`: فقط برای نسخه نمایشی، کد OTP را داخل رابط نشان می‌دهد.
- `OPENAI_API_KEY`: اختیاری؛ در نبود آن تحلیل داخلی جایگزین فعال است.
- `OPENAI_BASE_URL`: آدرس ارائه‌دهنده سازگار با OpenAI.
- `NESHAN_API_KEY`: کلید وب‌سرویس نشان؛ در نبود آن داده آزمایشی استفاده می‌شود.
- `NEXT_PUBLIC_APP_URL`: دامنه HTTPS نهایی.

فایل `.env` عمداً داخل ZIP تحویلی قرار نگرفته تا کلیدهای محرمانه منتشر نشوند.

## دستورات مهم

```bash
npm run typecheck
npm run lint
npm run build
npm start
npm run db:deploy
npm run db:seed
```

`db:seed` اطلاعات فعلی را پاک و داده نمونه جدید ایجاد می‌کند؛ روی دیتابیس دارای اطلاعات واقعی اجرا نکنید.

## کاربران نمونه

پس از اجرای seed:

| نقش | شماره موبایل |
| --- | --- |
| مدیر | `09120000001` |
| شهروند | `09120000002` |
| شهروند | `09120000003` |
| اپراتور شهرداری | `09120000004` |
| اپراتور آتش‌نشانی | `09120000005` |

در حالت `OTP_MODE=demo` کد ورود به‌صورت اعلان در رابط نمایش داده می‌شود.

## محدودیت آگاهانه MVP

OTP فعلاً در حافظه همان پردازش نگه‌داری می‌شود و حالت demo برای تست فعال است؛ بنابراین PM2 باید با یک instance اجرا شود. در نسخه نهایی، سرویس پیامک و یک ذخیره‌ساز مشترک برای OTP اضافه شود. SQLite برای تست چند کارفرما و ترافیک محدود کافی است، اما برای چند سرور یا ترافیک سنگین باید به PostgreSQL مهاجرت شود.
